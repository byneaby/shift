# Проверка новой версии на компьютере клуба

Эта версия готовит SHIFT к продаже другим клубам: лицензия, копии базы, обновление сервера по кнопке, своё название вместо SHIFT, импорт клиентов из старой системы, мастер первого запуска, сбор ошибок, изоляция филиалов, безопасность, тесты на деньги.

Здесь — как всё это проверить руками на том же компьютере, где стоит клуб, **ничего не сломав в рабочей базе**.

Подробности по отдельным темам: [SERVER-UPDATES.md](01_source_code/docs/SERVER-UPDATES.md), [BRANCH-ISOLATION.md](01_source_code/docs/BRANCH-ISOLATION.md), [FISCAL-INTEGRATION.md](01_source_code/docs/FISCAL-INTEGRATION.md).

---

## Главное правило

Проверяем на **отдельной базе и в отдельной папке**:

| | Рабочий клуб | Проверка |
|---|---|---|
| База | `shiftclub` | `shiftclub_test` |
| Папка сервера | `C:\ShiftClub\Server` | `C:\ShiftClub\Test` |
| Порт API | 5080 | **5090** |
| Панель | та, что выложена | `npm run dev` на 5173 |

Почему так:

- при старте API **сам накатывает миграции** — на рабочей базе это необратимо;
- мастер первого запуска и импорт клиентов пишут в базу;
- проверка обновления сервера останавливает службу API и подменяет папку целиком.

Отдельно про Telegram: не вписывайте в тестовый `secrets.env` токен бота клуба. Иначе тестовый сервер подключится к боту клуба и может разослать сообщения реальным клиентам. Нужен бот — заведите второго в @BotFather.

## Шаг 1. Взять код

Если проект уже клонирован на этом компьютере:

```powershell
cd <папка проекта>
git fetch origin
git checkout cursor/saas-readiness-fb14
git pull
```

Если нет — скачайте архив ветки с GitHub и распакуйте в любую папку, например `D:\ShiftTest`:

```powershell
Invoke-WebRequest `
  -Uri 'https://github.com/byneaby/shift/archive/refs/heads/cursor/saas-readiness-fb14.zip' `
  -OutFile 'D:\shift-test.zip'
Expand-Archive 'D:\shift-test.zip' -DestinationPath 'D:\ShiftTest'
```

Тот же архив скачивается кнопкой **Code → Download ZIP** на странице ветки. В архив попадают только файлы из git: дампа с данными клиентов и сборок в нём нет.

Что нужно установить: .NET SDK 8, Node.js 20+, PostgreSQL (тот, что уже стоит в клубе, подойдёт).

## Шаг 2. Тестовая база

```powershell
$env:PGPASSWORD = '<пароль postgres>'
& 'C:\Program Files\PostgreSQL\16\bin\psql.exe' -U postgres -c "CREATE DATABASE shiftclub_test OWNER shiftclub ENCODING 'UTF8'"
Remove-Item Env:\PGPASSWORD
```

База остаётся пустой — схему создадут миграции при первом старте API. Это важно: мастер первого запуска и выдача одноразовых паролей проверяются только на пустой базе.

Версия PostgreSQL в пути может быть другой (16/17/18) — посмотрите папку `C:\Program Files\PostgreSQL`.

## Шаг 3. Настройки тестового сервера

Создайте файл `01_source_code\src\ShiftClub.Server\secrets.env`:

```
ConnectionStrings__Default=Host=127.0.0.1;Port=5432;Database=shiftclub_test;Username=shiftclub;Password=<пароль роли shiftclub>
Jwt__SigningKey=<любая случайная строка от 32 символов>
Seed__ClubName=Тестовый клуб
Seed__TimeZone=Asia/Almaty
Seed__Currency=KZT
Backup__PgDumpPath=C:\Program Files\PostgreSQL\16\bin\pg_dump.exe
EnableSwagger=true
```

Пароль owner не задаём специально: на пустой базе сервер сам придумает одноразовые пароли и напечатает их в консоли один раз — это тоже часть проверки.

## Шаг 4. Запустить API и панель

В первом окне PowerShell:

```powershell
cd 01_source_code
dotnet run --project src\ShiftClub.Server --urls http://localhost:5090
```

В консоли должны появиться строки с паролями `owner` и админ-режима Shell — **скопируйте их сразу**. Проверка: http://localhost:5090/health

Во втором окне:

```powershell
cd 01_source_code\src\ShiftClub.Web
npm install
$env:SHIFTCLUB_API_URL = 'http://localhost:5090'
npm run dev
```

Панель откроется на http://localhost:5173, войти — `owner` и пароль из консоли.

## Что проверяем

Дальше всё в панели, раздел меню **«Система»**.

### 1. Мастер первого запуска — «Настройка клуба»

Открыть `/setup`. Должен быть чек-лист: название клуба, филиал, зоны, тарифы, компьютеры, касса — с отметками «сделано/не сделано» и ссылкой на нужную страницу.

- на пустой базе часть пунктов закрыта сразу (клуб и филиал созданы сидом), остальные — нет;
- заведите зону, тариф и компьютер → счётчик вверху вырастет;
- кнопка «Применить» в конце заполняет название, адрес, пояс и валюту.

Смысл: новый клуб доходит до первой продажи без звонка вам.

### 2. Оформление — «Оформление» (белый лейбл)

Открыть `/branding`. Поменять название, короткое название, цвет и загрузить логотип.

Проверить, что имя клуба подставилось вместо SHIFT:
- в меню слева и в заголовке браузера;
- на табло `/display`;
- в сообщениях Telegram-бота (если подключили своего тестового);
- в окне Shell, если будете его запускать.

### 3. Лицензия — «Лицензия»

По умолчанию `License__Enforce=false`, то есть сервер работает без ключа — так клуб не встанет из-за проблем с лицензией в середине смены. Чтобы проверить сам механизм, добавьте в `secrets.env` и перезапустите API:

```
License__Enforce=true
License__PublicKey=<публичный ключ из keygen>
```

Ключи выдаёт утилита поставщика:

```powershell
cd 01_source_code
dotnet run --project tools\ShiftClub.LicenseTool -- keygen
dotnet run --project tools\ShiftClub.LicenseTool -- issue --private <приватный> --club "Тестовый клуб" --pc 5 --days 30
```

Приватный ключ остаётся только у вас: им подписываются лицензии. В git он не попадает и в клуб не уезжает.

Что посмотреть на странице `/license`:

- вставить ключ → появились название клуба, тариф, срок, лимит ПК и список возможностей;
- выдать ключ на `--days -1 --grace 0` → состояние «просрочена», при этом смены и касса продолжают работать, а в панели висит предупреждение (с `--grace 14` то же самое покажется как «льготный период»);
- выдать ключ с `--pc 1`, когда компьютеров больше → видно превышение лимита;
- выдать ключ без `shift_case` (`--features multi_branch,telegram_crm,kaspi_pos`) → пункт «Кейсы» исчезает из меню, а попытка изменить кейсы отвечает 403. История кейсов при этом сохраняется.

### 4. Копии базы — «Копии базы»

Открыть `/backups`:

- «Сделать копию» → в списке появляется файл, рядом — размер и время;
- файл лежит в `src\ShiftClub.Server\data\backups`, открывается `pg_restore`;
- копии старше `Backup__KeepDays` удаляются сами;
- копия делается и автоматически: раз в сутки в `Backup__DailyHourLocal` и **перед каждой миграцией**.

Если на странице ошибка «не найден pg_dump» — поправьте `Backup__PgDumpPath` в `secrets.env`.

### 5. Состояние — «Состояние»

Открыть `/system`. Здесь то, что раньше приходилось смотреть в логах на сервере:

- версия сервера, время работы, база, место на диске;
- проверки: база, миграции, pg_dump, лицензия, копии;
- последние ошибки с версией и названием клуба — телефоны, имена и токены из них вырезаются, так что скриншот этой страницы можно присылать поставщику.

В норме список ошибок пустой — так и должно быть. Чтобы увидеть, как он работает: впишите в `secrets.env` заведомо неверный `Backup__PgDumpPath`, перезапустите API и нажмите «Сделать копию» на странице копий. Копия не выйдет, а на странице «Состояние» появится запись об ошибке. После проверки верните правильный путь.

Собираются не только ошибки запросов, но и падения фоновых задач — копий базы, Telegram, завершения сеансов.

### 6. Импорт клиентов — «Импорт клиентов»

Открыть `/customers/import`. Нужен CSV из старой системы; для проверки хватит такого файла:

```
phone,first_name,last_name,balance,bonus
+77011234567,Иван,Петров,1500,100
+77019876543,Пётр,Иванов,0,0
```

Порядок:

- вставить/загрузить файл → **предпросмотр**: сколько создастся, сколько обновится, сколько пропустим, сколько денег встанет на балансы, какие колонки распознаны, какие строки с проблемами;
- импортировать → клиенты появились, балансы совпали;
- **импортировать тот же файл второй раз** → клиенты не продублировались и балансы не удвоились (это главная проверка);
- в карточке клиента у начального баланса есть проводка — деньги не появились «из ниоткуда».

### 7. Филиалы

Проверка имеет смысл, если филиалов больше одного. Создайте второй филиал и сотрудника, привязанного к нему, затем войдите им:

- в списках зон, тарифов, компьютеров, касс, уровней лояльности видно только свой филиал;
- в переключателе филиалов — только свой;
- создать тариф или компьютер в чужом филиале не получится (ответ 403 «Этот филиал вам не доступен»);
- открыть смену на кассе чужого филиала нельзя;
- у владельца (право `branches.manage`) доступ ко всей сети, как раньше.

Филиал теперь берётся из токена сотрудника, а не из запроса браузера.

### 8. Безопасность

- вход с неверным паролем 11 раз подряд → с 11-й попытки ответ 429 (защита от подбора);
- запрос к API с чужого домена отклоняется (локальная сеть разрешена всегда, внешние домены — через `Cors__AllowedOrigins`);
- в ответах есть заголовки `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`;
- Swagger выключается флагом `EnableSwagger=false` — на рабочем сервере он должен быть выключен.

### 9. Фискальный регистратор

Пока это точка подключения, а не готовая интеграция: в коде есть интерфейс и «пустая» реализация, которая ничего не печатает. Проверять нечего — важно, что продажи и возвраты уже идут через одну точку, и подключение конкретной модели не потребует переписывать кассу. Подробности в [FISCAL-INTEGRATION.md](01_source_code/docs/FISCAL-INTEGRATION.md).

### 10. Автотесты

```powershell
cd 01_source_code
$env:SHIFTCLUB_TEST_DB = "Host=127.0.0.1;Port=5432;Database=shiftclub_tests;Username=shiftclub;Password=<пароль>"
dotnet test ShiftClub.sln
```

Ожидаемо: все 156 тестов зелёные. Тесты на деньги идут на настоящем PostgreSQL и создают **свою** базу `shiftclub_tests` — рабочую указывать нельзя. Если базы нет, они не падают, а помечаются как пропущенные.

## 11. Обновление сервера по кнопке — отдельно и осторожно

Это самая рискованная проверка: скрипт останавливает API и подменяет папку сервера целиком. Делайте её **на копии** папки сервера, не на рабочей.

Сначала соберите выпуск (это делается у поставщика, не в клубе):

```powershell
cd 01_source_code
.\scripts\Publish-ServerUpdate.ps1 -Version 0.9.0 -ReleaseNotes "Проверка обновления"
```

В `dist\feed\server\stable` появятся `ShiftClub.Server-0.9.0.zip` и `manifest.json`.

### Вариант А — только скрипт подмены (быстрее и безопаснее)

Скопируйте папку сервера в `C:\ShiftClub\Test`, запустите её на порту 5090 и выполните:

```powershell
.\scripts\Update-ShiftClubServer.ps1 `
  -PackagePath D:\...\dist\feed\server\stable\ShiftClub.Server-0.9.0.zip `
  -Version 0.9.0 `
  -ServerDir C:\ShiftClub\Test `
  -HealthUrl http://127.0.0.1:5090/health
```

Что должно получиться:

- старая папка целиком отложена в `C:\ShiftClub\server-rollback\<версия-время>`;
- `secrets.env`, `appsettings.Production.json`, `data` и `logs` остались на месте — настройки и данные клуба не потерялись;
- сервер поднялся, `/health` отвечает, журнал подмены — в `C:\ShiftClub\shiftclub-update.log`.

Теперь проверка отката — она важнее успешного обновления. Испортите пакет (например, положите в zip битый `ShiftClub.Server.dll`) и повторите команду: сервер не поднимется, скрипт вернёт отложенную папку и запустит старую версию. Клуб должен остаться рабочим.

### Вариант Б — полностью через панель

Нужен канал обновлений, доступный по HTTP. Разложите папку так, чтобы манифест открывался по адресу `<FeedUrl>/server/stable/manifest.json`, и добавьте в `secrets.env`:

```
ServerUpdates__FeedUrl=http://<адрес с файлами>
```

После перезапуска на странице `/system` появится раздел «Версия сервера»: текущая версия, доступная версия, что нового. Кнопка «Обновить» есть только у владельца. По нажатию сервер сначала делает копию базы (если копия не вышла — обновление отменяется), потом запускает тот же скрипт подмены. Сервер при этом перезапустится, панель на пару минут потеряет связь — это нормально.

Пустой `FeedUrl` (как в поставке) означает «обновления только руками»: раздел в панели сообщит, что канал не настроен.

## Если что-то пошло не так

- **Рабочую базу не трогали** — тестовая `shiftclub_test` удаляется одной командой: `DROP DATABASE shiftclub_test;`
- Сервер после подмены не поднялся — скрипт откатывается сам; если нужно вернуть вручную, папка лежит в `server-rollback`, достаточно вернуть её на место и запустить задачу `ShiftClubApi`.
- Что именно произошло при обновлении — в `shiftclub-update.log` рядом с папкой сервера.
- Ошибки сервера — страница `/system` и `logs` в папке сервера.
